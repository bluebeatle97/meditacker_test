# 액팅 보드 구현 지시서 (Claude Code 용)

작성 2026-08-12 · 대상 브랜치 `plan-v2-rebuild` · 이 문서 하나로 구현을 시작할 수 있게 쓴 것

> **너(Claude Code)의 임무**: 이 저장소에 "액팅 보드"를 구현한다.
> UI·동작의 기준은 `docs/액팅보드_프로토타입.html` (브라우저에서 열어 직접 조작해 볼 것),
> 설계 근거는 `docs/액팅보드_설계.md`, 기존 기능 지도는 `docs/기능정리.md` 다.
> 이 지시서와 프로토타입이 어긋나면 **프로토타입이 정답**이다.

## 0. 컨텍스트 요약 (왜 만드는가)

피부과의 환자 동선 관리(누구를 어느 방에, 어느 의료진과)가 액팅팀에 집중되어 과중하다.
비콘 RTLS(이 저장소)가 이미 위치·체류를 실시간으로 알고 있으므로, **상태 파악과 지시 전파를
화면이 흡수하고 판단만 사람에게 남기는 디스패처 보드**를 만든다.

기존 시스템 이해에 필요한 최소 지식:

- `packages/server` — 수집(MQTT)→존 판정→좌표 추정→Socket.IO 방송. HTTP API 는 `src/index.ts` 에 라우트 나열
- `packages/web-staff` — Phaser 지도 화면 (5173). **이 화면은 건드리지 않는다** — 보드는 별도 진입점
- `packages/web-patient` — 환자 폰 화면 (5174). 길 안내 화살표 기존 구현 있음
- `packages/shared` — 공용 타입·계산. 세 앱이 같이 쓰는 값은 반드시 여기로
- DB 는 better-sqlite3, 스키마 `packages/server/src/db/schema.sql`
- 기존 테스트 82개 — **전부 통과 상태 유지**가 전제

## 1. 구현 범위 (이번 작업)

**신규 화면 1개** — `/board` (서버 정적 서빙 또는 web-staff 워크스페이스 내 별도 페이지, `/monitor` 방식 참고).
뷰 4종: `팀장` / `팀원` / `인포·상담 스테이션` / `피부·시술 스테이션`.
레이아웃은 전 뷰 공통 3컬럼: **환자 대시보드(좌) | 방 카드 그리드(중) | 의료진 목록(우)**.

환자 앱에는 버튼 2개 추가: **통역 요청**(외국어 배정만 노출), (기존 설계의) 화장실 안내는 이번 범위 제외.

## 2. 데이터 변경

### 2-1. DB (schema.sql 에 추가)

```sql
-- 배정에 플랜·언어 (인포 기입, 상담 업데이트)
ALTER TABLE assignments ADD COLUMN plan TEXT;
ALTER TABLE assignments ADD COLUMN lang TEXT;            -- null=한국어, '中文', 'EN' 등
ALTER TABLE assignments ADD COLUMN course TEXT;          -- 코스 템플릿 JSON: {"consult":true,"skin":"pre"} — null 허용

-- 이동 오더 (액팅 배정 → 담당 팀 승인 → 안내 → 도착) 상태 머신
CREATE TABLE IF NOT EXISTS move_orders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  assignment_id INTEGER NOT NULL,
  to_zone TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'ordered',  -- ordered | approved | rejected | moving | arrived | cancelled
  ordered_by TEXT,                          -- 액팅 (스테이션이면 PIN 인증자)
  answered_by TEXT,                         -- 승인/거절한 사람 (PIN 인증자)
  ordered_at INTEGER NOT NULL,
  answered_at INTEGER,
  arrived_at INTEGER
);

-- 행동 체크포인트 (상담 완료 / 마취 완료 / 시술 완료 ...)
CREATE TABLE IF NOT EXISTS checkpoints (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  assignment_id INTEGER NOT NULL,
  zone_id TEXT NOT NULL,
  label TEXT NOT NULL,
  by_pin TEXT, by_name TEXT,               -- 누른 사람 (비콘 PIN 인증)
  at INTEGER NOT NULL
);

-- 보드 화면 배치 (모듈 순서) — 뷰·기기별
CREATE TABLE IF NOT EXISTS board_prefs (
  view TEXT NOT NULL, device_key TEXT NOT NULL,
  sections TEXT NOT NULL,                   -- JSON 배열
  PRIMARY KEY (view, device_key)
);
```

### 2-2. 설정 파일

`packages/server/src/config/proc-times.json` — 시술별 예상시간 사전.
프로토타입의 `PROC_TIMES` 배열 형식 그대로: `[{ "k": "울쎄라", "alias": ["울세라"], "min": 40 }, …]`.
⚠ 프로토타입 값은 임시다 — **파일에 "임시값, 현장 표로 교체 예정" 주석을 남길 것**.
매칭 로직(`planMinutes`: 공백 제거·소문자 정규화 후 포함 매칭, 합산, 실패 시 방 종류 기본값)은
**shared 패키지**에 둔다 — 보드와 서버가 같은 계산을 써야 한다.

## 3. 서버 API (전부 기존 index.ts 라우트 패턴 따름)

| 메서드·경로 | 하는 일 | 권한 |
|---|---|---|
| `POST /station-auth` | `{pin}` → 등록된 **직원 비콘 MAC 뒷4자리** 대조 → `{name, token}` 스테이션 세션 토큰 | — |
| `POST /plan` | `{tagId, plan, lang?}` 플랜 저장/수정 | staff 또는 스테이션 토큰 |
| `POST /course` | `{tagId, consult, skin}` 코스 템플릿 저장 | staff |
| `POST /move-order` | `{tagId, zoneId}` 이동 오더 생성 (status=ordered) | staff |
| `POST /move-order/:id/approve` | 승인 → status=approved → **이때 기존 `/guide` 로직 호출**(화살표 발행) → moving | 스테이션 토큰 |
| `POST /move-order/:id/reject` | 거절 → rejected, 환자 대기 복귀 | 스테이션 토큰 |
| `POST /checkpoint` | `{zoneId, label}` 체크포인트 기록 | 스테이션 토큰 |
| `POST /register-patient` | `{tagId, name, plan, lang?}` — 기존 `/assign` 확장 (plan·lang 동시 저장) | 스테이션 토큰 |
| `POST /itp-request` | 통역 요청 (환자 JWT — `/patient-token` 발급분) | 환자 토큰 |
| `POST /itp-request/:id/answer` | `{accept: bool}` | staff/스테이션 토큰 |
| `GET/PUT /board-prefs` | 모듈 배치 조회/저장 | staff/스테이션 |

도착 판정: 기존 navigation_logs 의 도착 감지(존 진입)를 move_orders 에도 연결 — 환자가 to_zone
진입 시 status=arrived, arrived_at 기록. **기존 /guide·navigation_logs 코드를 재사용하고 중복 구현 금지.**

소켓: `/staff` 네임스페이스에 이벤트 추가 — `board:orders`(오더 목록 변경 시), `board:checkpoint`,
`board:itp`. 페이로드 타입은 `packages/shared/src/index.ts` 에 선언부터 추가할 것.

## 4. 보드 화면 스펙 (핵심 — 프로토타입 그대로)

### 4-1. 파생 상태 (입력 없음 — 서버 방송 데이터에서 계산)

- 방 상태: `비어 있음(N분)` / `사용 중` / `진행 중`(의료진 재실) / `승인 대기` / `이동 중` /
  `완료—이동 대기`(마지막 체크포인트 완료) / `의료진 미입실`(환자만 5분+, 시술 계열) /
  `기준 초과`(체류 > 기준시간)
- **기준시간** = 재실 환자 플랜의 `planMinutes` 합 (시술·수술·레이저·피부관리), 실패 시 방 종류 기본값
- 환자 상태: `대기`(이동 지시 없음 + 진료 미진행 — **대기공간·복도·완료 후 방 안 전부 포함**) /
  `승인 대기` / `이동 중` / `진행 중` / `위치 미상`
- 코스: `{consult, skin}` 2토글 → 단계열 생성 (데스크는 표시 안 함). 다음 단계 제안은 확정적
- 마지막 체크포인트 완료 시: 환자는 대기 줄로 자동 이동(완료 후 경과=대기시간), 완료 단계는 코스에서 지움

### 4-2. 뷰별 권한 매트릭스

| 기능 | 팀장 | 팀원 | 인포·상담 | 피부·시술 |
|---|---|---|---|---|
| 환자 DnD 배정·동선 변경 | ○ (상담실 제외) | ○ | ✕ | ✕ |
| 의료진 DnD 호출 | ○ (의사·간호사는 시술·수술·레이저·피부·회복만, **통역은 전체**) | ✕ | ✕ | ✕ |
| 환자 등록 폼 (이름+플랜+언어) | ✕ | ✕ | ○ | ✕ |
| 플랜 수정 (이름 클릭) | ○ | ○ | ○ | ✕ (보기만) |
| 상담 완료 (플랜 확인 강제) | ✕ | ✕ | ○ | ✕ |
| 완료 확인 버튼 (마취·시술 등) | ✕ | ✕ | 상담실만 | 담당 방만 |
| 배정 승인/거절 | ✕ | ✕ | 상담실 오더 | 시술 계열 오더 |
| 코스 설정 (2×3 격자) | ○ | ○ | ✕ | ✕ |
| 모듈 배치 변경 (확인창) | ○ | ○ | ○ | ○ |
| 대기 줄 필터 | 시술 영역만 (+그 외 접힘) | 상담·전관리만 (+그 외 접힘) | 전체 | 전체 |

- 팀장 영역 판정: 시술·수술·레이저·회복 재실 or 다음 단계가 `시술`/`피부(후)`
- 스테이션 쓰기 조작은 전부 **PIN 인증**(스테이션 토큰) 후, 기록에 인증자 이름 저장
- 모듈 기본 순서 — 팀장·피부시술: 시술 계열 위 / 팀원·인포상담: 상담 위

### 4-3. 상호작용 규칙

- **조작은 드래그앤드롭이 기본**, 화면 배치(모듈) 변경만 확인창을 거친다
- 배정 승인 팝업은 담당 스테이션 **화면 정중앙** 고정, 응답 전까지 유지. 3분 미응답 시 액팅에 "승인 지연" 알림
- 알림은 본문에 쌓지 않는다: 우측 상단 🔔 탭(활성 수 뱃지, 미확인 시 빨간 깜빡) + 신규 발생 시
  우측 하단 카톡식 슬라이드 팝업(동시 2개, 자동 소멸). 토스트도 동시 2개까지
- **한 화면 원칙**: 페이지 스크롤 금지, 컬럼 내부 스크롤만
- 브라우저 스토리지 사용 금지 (설계 불변식 B-5) — 배치·인증 세션은 서버 저장

## 5. 환자 앱 (web-patient) 추가

- 배정에 `lang` 이 있으면 상단에 `💬 통역 요청` 버튼 노출 → `POST /itp-request` → 요청 후
  버튼 비활성 + "통역사에게 알렸어요" → 수락되면 "통역사가 가고 있어요" (기존 소켓으로 상태 수신)
- 요청 쿨다운 5분. 통역 위치 추적은 이미 있으므로 서버는 요청에 환자 현재 존을 첨부

## 6. 구현 순서 (커밋 단위 제안)

1. shared: 타입·코스 유틸·planMinutes + proc-times.json + 테스트
2. DB 마이그레이션 + move_orders/checkpoints CRUD + 테스트
3. 서버 API + 소켓 이벤트 (기존 /guide·navigation_logs 재사용 연결) + 테스트
4. 보드 화면: 레이아웃·파생 상태 렌더 (읽기 전용 상태로 먼저)
5. DnD 배정 + 승인 플로우 + PIN 인증
6. 스테이션 분화·완료 버튼·등록 폼·플랜 팝업
7. 통역 요청 (서버 + 환자 앱 + 보드 수신)
8. 모듈 커스터마이징 + 알림 시스템

## 7. 수용 기준 (전부 만족해야 완료)

- [ ] 프로토타입의 시나리오가 실데이터로 재현된다: 팀장이 대기 환자를 빈 시술실에 드래그 →
      피부·시술 스테이션 중앙에 승인 팝업 → PIN 수락 → 환자 폰 화살표 → 도착 시 진행 중 전환
- [ ] 상담 완료 버튼은 플랜 확인·수정 창을 거쳐야 완료된다
- [ ] 마지막 체크포인트 완료 시 환자가 대기 줄로 이동하고 방 카드가 "완료—이동 대기"가 된다
- [ ] 플랜 "울쎄라 300샷 + 보톡스" 재실 방의 기준시간이 50분으로 표시되고 초과 시 빨간 경고
- [ ] 잘못된 PIN 은 거부되고, 모든 스테이션 조작 기록에 인증자 이름이 남는다
- [ ] 의사 카드를 상담실에 드롭할 수 없고, 통역 카드는 가능하다
- [ ] 기존 테스트 82개 + 신규 테스트 전부 통과, 기존 지도 화면(5173)·관제(/monitor) 동작 불변
- [ ] `npm run dev:all` 만으로 보드가 뜬다 (별도 절차 없음)

## 9. 하지 말 것

- 존 판정·좌표 추정·MQTT 수집 코드 수정 금지 (보드는 소비자다)
- 시술 코드·구조화 입력 UI 추가 금지 — 플랜은 자유 텍스트 한 줄 + 사전 매칭까지만
- 베가스 연동 시도 금지 (API 없음)
- 로그인/계정 시스템 도입 금지 — 인증은 비콘 PIN 스테이션 토큰까지만
- `localStorage`/`sessionStorage` 사용 금지
