# 원내 서버 세팅 (기동용)

병원에서 실제로 돌릴 서버를 처음부터 만드는 절차다. **개발할 때 쓰는 `npm run dev:all`
구성과 다르다** — 그건 사람이 지켜보는 동안만 도는 구성이고, 여기는 아무도 안 볼 때도
돌아야 한다.

위에서 아래로 순서대로 하면 된다. **각 단계 끝에 "확인" 이 있다. 확인이 안 되면 다음
단계로 넘어가지 말 것** — 안 그러면 마지막에 안 될 때 어디가 문제인지 못 찾는다.

---

## 무엇이 어디서 도나

```
비콘 (사람이 들고 다님)
  │ BLE 광고
  ▼
게이트웨이 6대  ── WiFi(GOAT_gateway) ──┐
                                        │ MQTT (1883)
                                        ▼
                              ┌──────────────────────┐
                              │  원내 서버 PC        │
                              │                      │
                              │  ① mosquitto (1883)  │  ← 게이트웨이가 신호를 던지는 곳
                              │  ② meditracker(8080) │  ← 그걸 읽어 방을 판정하고 화면을 만든다
                              └──────────────────────┘
                                        │ 8080
                                        ▼
                     직원 폰·데스크 PC (같은 WiFi 에서 접속)
```

프로그램이 **두 개**다. 둘 다 윈도 서비스로 만들어서 PC 를 켜면 알아서 뜨게 한다.

| | 무엇 | 어떻게 서비스가 되나 |
|---|---|---|
| ① | mosquitto (MQTT 브로커) | 설치하면 서비스가 자동 등록된다 |
| ② | meditracker (서버 + 화면) | nssm 으로 등록한다 |

> **개발 구성과 다른 점 세 가지**
> - 브로커: `dev:broker`(aedes) 대신 **mosquitto**
> - 앱: `dev:all`(Vite 5173/5174) 대신 **8080 하나**가 화면까지 전부 서빙
> - 핀: 개발은 핀 없이 들어오지만, 기동은 **핀이 실제로 걸린다**

## 1단계 — PC 가 자면 안 된다

자다 깨면 게이트웨이 연결이 전부 끊긴다. 관리자 PowerShell 에서:

```powershell
powercfg /change standby-timeout-ac 0
```

```powershell
powercfg /hibernate off
```

**확인** — 아래 명령의 AC 값이 `0x00000000` 이면 안 잠든다는 뜻이다.

```powershell
powercfg /query SCHEME_CURRENT SUB_SLEEP STANDBYIDLE
```

---

## 2단계 — `GOAT_gateway` 에 붙이고 IP 를 고정한다

게이트웨이 설정에는 서버 주소가 **IP 숫자로 박혀 있다.** IP 가 바뀌면 게이트웨이 6대가
전부 서버를 못 찾고, 신호가 **한 건도** 안 온다.

지금 IP 확인:

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.InterfaceAlias -eq 'Wi-Fi' }
```

`PrefixOrigin` 이 `Dhcp` 로 나오면 **바뀔 수 있다는 뜻이다.** 공유기 관리 페이지에서 이 PC 에
**DHCP 예약(고정 IP)** 을 걸어라. 이걸 안 하면 재부팅할 때마다 게이트웨이 6대 설정을 다시
만지게 된다.

**확인** — 재부팅해도 같은 IP 가 나온다. (2026-08-18 실측 기준 `192.168.1.91`)

---

## 3단계 — 방화벽 구멍 두 개

```powershell
New-NetFirewallRule -DisplayName 'MQTT 1883' -Direction Inbound -Protocol TCP -LocalPort 1883 -Action Allow
```

```powershell
New-NetFirewallRule -DisplayName 'meditracker 8080' -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

- 1883 = 게이트웨이가 신호를 보내는 문
- 8080 = 직원 단말이 화면을 보는 문

윈도는 `GOAT_gateway` 를 **Public** 으로 분류한다. 위 명령은 프로필을 안 적었으니 모든
프로필에 적용된다 — 규칙을 손으로 만들 거면 **Public 을 반드시 포함**해야 한다. Private
만 걸면 신호가 한 건도 안 온다.

> 개발 PC 에는 `node.exe` 를 통째로 허용한 규칙이 붙어 있을 수 있다. 기동 PC 에서는 그걸
> 지우고 위 두 포트만 남기는 게 맞다.

## 4단계 — mosquitto 설치

설치본을 실행하면 윈도 서비스로 자동 등록된다.

**설치만 하면 안 된다.** mosquitto 2.x 는 기본값이 **자기 PC 안에서만 받기** 라서, 그대로
두면 게이트웨이가 죽을 때까지 못 붙는다. `C:\Program Files\mosquitto\mosquitto.conf` 를
관리자 권한 메모장으로 열어 맨 아래에 두 줄을 추가한다:

```
listener 1883
allow_anonymous true
```

저장하고 서비스 재시작:

```powershell
Restart-Service mosquitto
```

**확인 1** — Status 가 `Running`

```powershell
Get-Service mosquitto
```

**확인 2** — 아래 결과에 `0.0.0.0:1883` 이 보인다. `127.0.0.1:1883` 만 보이면 위 두 줄이
안 먹은 것이다.

```powershell
netstat -ano | findstr :1883
```

> `allow_anonymous true` 는 **비번 없이 아무나 붙을 수 있다**는 뜻이다. 게이트웨이 전용 망이라
> 지금은 이대로 두지만, 기동 전에 게이트웨이 계정을 발급해서 막아야 한다.

## 5단계 — 코드 받고 화면 빌드

저장소 폴더에서:

```bash
npm install
```

```bash
npm run build:demo
```

화면(직원용·환자용)을 파일로 구워 두는 단계다. 이걸 해두면 서버 8080 **하나가** 화면까지
같이 내보내므로, 기동에서는 Vite(5173/5174)를 띄울 필요가 없다.

> 코드를 고칠 때마다 이 명령을 다시 돌려야 화면에 반영된다. 안 돌리면 **서버만 새 코드,
> 화면은 옛 코드**가 된다.

**확인** — `packages/web-staff/dist/index.html` 파일이 생겼다.

## 6단계 — 비밀값 넣기 (`.env`)

`packages/server/.env` 파일을 만들고 세 줄을 넣는다:

```
NODE_ENV=production
STAFF_PIN=<직원들이 입력할 핀>
JWT_SECRET=<아래 명령으로 만든 긴 문자열>
```

`JWT_SECRET` 만들기:

```bash
openssl rand -hex 32
```

- `STAFF_PIN` — 직원용·관제 화면에 들어갈 때 입력하는 값. 기본값(`000111`)을 그대로 쓰면 안 된다
- `NODE_ENV=production` — **이게 없으면 핀이 무의미해진다.** 개발 모드에서는 핀을 안 묻고
  토큰을 내주는 창구가 열려 있다

**확인** — 파일 이름이 `.env` 다 (`.env.example` 이 아니다).

## 7단계 — 손으로 한 번 띄워서 되는지 본다

서비스로 만들기 **전에** 반드시 이걸 먼저 한다. 서비스는 오류가 화면에 안 보이기 때문에,
안 되는 상태로 서비스를 만들면 원인 찾기가 훨씬 어려워진다.

```bash
npm run start -w @meditracker/server
```

**확인 1** — 창에 `[ingestion] MQTT connected` 가 뜬다
**확인 2** — 브라우저에서 `http://localhost:8080/health` 가 `{"ok":true...}` 를 준다
**확인 3** — 다른 폰에서 `http://<서버IP>:8080` 을 열면 핀 상자가 뜬다

여기까지 되면 `Ctrl+C` 로 끄고 다음 단계로. 안 되면 맨 아래 **"안 될 때"** 를 먼저 보라.

## 8단계 — nssm 으로 서비스 등록

PC 를 켜면 사람이 로그인하지 않아도 서버가 알아서 뜨게 만드는 단계다.

먼저 로그 폴더를 만든다 (없으면 nssm 이 로그를 못 쓴다):

```powershell
New-Item -ItemType Directory -Force C:\meditracker\logs
```

nssm 을 압축 해제한 폴더에서 관리자 PowerShell 로:

```powershell
.\nssm.exe install meditracker
```

창이 뜨면 이렇게 채운다 (경로는 실제 설치 위치에 맞게):

| 탭 | 항목 | 값 |
|---|---|---|
| Application | Path | `C:\Program Files\nodejs\node.exe` |
| Application | Startup directory | 저장소 폴더 (예 `C:\meditracker`) |
| Application | Arguments | `node_modules\tsx\dist\cli.mjs packages\server\src\index.ts` |
| I/O | Output (stdout) | `C:\meditracker\logs\out.log` |
| I/O | Error (stderr) | `C:\meditracker\logs\err.log` |
| Exit actions | Restart | 기본값(재시작) 그대로 둔다 |

> **왜 `npm` 이 아니라 `node.exe` 냐** — `npm.cmd` 같은 배치 파일을 서비스로 돌리면 중간
> 프로세스가 하나 더 생겨서, 실제 서버가 죽었는지 살았는지 nssm 이 제대로 못 본다. node 를
> 직접 부르면 그 문제가 없다.
>
> **왜 `tsx` 냐** — 이 프로젝트는 서버를 TypeScript 그대로 실행한다 (`@meditracker/shared`
> 가 TS 소스를 내보내기 때문). 배포 이미지에서도 같은 방식으로 돌린다.

서비스 시작:

```powershell
Start-Service meditracker
```

**확인 1** — Status 가 `Running`

```powershell
Get-Service meditracker
```

**확인 2** — `http://localhost:8080/health` 가 응답한다
**확인 3** — `C:\meditracker\logs\err.log` 가 비어 있다

## 잘 도는지 보는 법

주소창에 이걸 치면 서버가 지금 뭘 받고 있는지 한 줄로 나온다:

```
http://<서버IP>:8080/health
```

숫자 두 개만 보면 된다:

| 값 | 뜻 |
|---|---|
| `tags` | **지금 화면에 뜨는 사람 수.** 0 이면 화면이 빈다 |
| `acceptedScans` | 통과한 신호 누적. 새로고침해서 **숫자가 늘면 살아 있는 것** |

---

## 안 될 때

`/health` 의 숫자로 어디가 막혔는지 갈린다. 위에서부터 내려가며 맞는 줄을 찾아라.

| 증상 | 원인 | 할 일 |
|---|---|---|
| `/health` 자체가 안 열린다 | 서버가 안 떠 있다 | `Get-Service meditracker`, `logs\err.log` |
| 숫자가 전부 0 이고 하나도 안 오른다 | **신호가 도착조차 안 한다** | IP 바뀜 · 방화벽 · mosquitto 가 `127.0.0.1` 만 듣는 중 · 게이트웨이 전원 |
| `uniqueUnknownIds` 만 오른다 | 신호는 오는데 **비콘이 미등록** | 관제 화면 **미등록 신호** 에서 등록 |
| `idleScans` 만 오른다 | 등록은 됐는데 **아무도 안 들고 있다** | 직원용 화면에서 **환자 등록(배정)** |
| `acceptedScans` 는 오르는데 방이 엉뚱하다 | 게이트웨이 배치·파라미터 | README "3. 현장 튜닝" |

> 제일 헷갈리는 게 `idleScans` 줄이다. 장비가 다 정상이고 신호도 다 들어오는데 화면만 텅
> 비어 있어서 고장으로 보인다. **등록과 배정은 다른 일이다** — 등록은 "이 비콘은 우리 것"
> 이고, 배정은 "이 비콘을 이 사람이 들고 있다" 다. 배정이 없으면 화면에 안 뜬다.

로그 위치:

```
C:\meditracker\logs\out.log     정상 로그
C:\meditracker\logs\err.log     오류
```

## 아직 안 되는 것 (기동 전 해결 필요)

1. **환자용 화면·QR 진입** — 게이트웨이 WiFi 가 업무망과 VLAN 으로 분리돼 있어서, 그 안에
   있는 서버는 환자 폰에서 안 보인다. 서버가 두 망에서 모두 보이는 자리로 옮겨야 한다
   (NIC 2개, 또는 업무망 → 게이트웨이망 라우팅 허용)
2. **mosquitto 익명 접속 허용** — 4단계의 `allow_anonymous true` 를 게이트웨이 계정으로 교체
3. **게이트웨이 실동작 대수** — 등록 6대 중 실제로 신호를 올리는 대수를 맞춰야 한다.
   관제 화면의 게이트웨이 표에서 확인
