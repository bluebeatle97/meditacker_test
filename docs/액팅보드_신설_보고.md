# 액팅보드 신설 보고

보고일 2026-08-12 · 작성 개발팀 · 첨부 프로토타입 `docs/액팅보드_프로토타입.html`

---

## 한 줄 요약

액팅팀에 집중된 환자 동선 관리 업무를 덜기 위해, 이미 구축한 실내 위치추적(비콘) 위에
**"액팅 보드"** 화면 하나를 신설합니다. 방 상태와 환자·의료진 위치가 입력 없이 자동으로 뜨고,
배정은 드래그 한 번, 환자 안내는 환자 폰 화살표로 자동 전달됩니다.

---

## 1. 배경 — 지금의 문제

환자 동선 관리와 베드 배정의 판단·권한이 전부 액팅팀에 몰려 있습니다.
액팅팀의 하루는 세 가지 일의 반복입니다.

| 일 | 지금 방식 | 비중 |
|---|---|---|
| ① 상태 파악 — "3번방 비었어?" "김OO 어디?" | 무전으로 물어보거나 직접 가서 확인 | 가장 큼 |
| ② 판단 — 누구를 어느 방에, 어느 의료진과 | 머릿속 + 베가스 차트 | 중간 |
| ③ 지시 전파 — "김OO 님 3번방으로" | 무전 + 직접 안내 | 중간 |

①과 ③이 무전 트래픽의 대부분이고, 이것이 과중의 실체입니다.
②(판단)는 사람이 해야 하고, 앞으로도 액팅팀이 합니다 — 권한 구조는 바꾸지 않습니다.

## 2. 이미 갖춰진 기반

자체 개발한 **메디트래커**(비콘 실내 위치추적)가 준비되어 있습니다.

- 환자·직원이 지닌 비콘의 위치를 방 단위로 실시간 판정 (도면 위 표시)
- 환자 폰 길 안내: 직원이 목적지를 지정하면 환자 폰에 바닥 화살표가 뜨고, 도착하면 자동 해제
- 입퇴실·체류시간·안내 소요시간이 전부 자동 기록됨
- 실장비 연동 검증 완료, 게이트웨이 전체 설치만 남은 단계

## 3. 액팅 보드 — 무엇이 달라지나

지도("어디 있나")와 별도로, 디스패처를 위한 **"다음에 뭘 해야 하나"** 화면을 신설합니다.

**아무도 입력하지 않아도 자동으로 보이는 것** (위치추적에서 도출):

- 방마다: 비어 있음(몇 분째) / 사용 중(누가, 몇 분째) / 진행 중(의료진 입실) 상태
- ⚠ **환자 입실 후 의료진 미입실** 경고 — 방치되는 환자를 즉시 발견
- ⏱ **기준 시간 초과** 경고 — 방 회전 지연을 즉시 발견
- 의료진 실시간 위치 줄 — **대기 중인 의사가 한눈에** (배정 가능 표시)
- 환자 줄: 대기(오래된 순)·이동 중·진행 중·위치 미상

**액팅팀의 조작은 두 가지뿐**:

- 환자를 빈 방에 **드래그 한 번** → 환자 폰에 화살표 안내 자동 전송, 도착 시 자동 확인
- 환자 이름을 누르면 **플랜(시술 내용)** 이 떠서, 베가스를 오가지 않고 보드 안에서 판단

같은 화면의 **읽기 전용 버전**을 각 팀 스테이션(데스크·피부실·시술부)에 걸어,
각 팀이 "다음 누구 와?"를 스스로 보게 합니다 — 조작 권한은 여전히 액팅팀만 갖습니다.

## 4. 팀별 업무 변화

| 팀 | 달라지는 것 | 부담 |
|---|---|---|
| **인포팀** | 접수 때 환자 이름 + **플랜(시술 내용)** 을 기입 (기존 이름 입력에 플랜 한 줄 추가) | 소폭 증가 |
| **상담팀** | 상담 후 플랜이 바뀌면 보드에서 **플랜 업데이트** | 소폭 증가 |
| **액팅팀** | 무전 폴링·구두 안내 → 보드 확인 + 드래그 배정. 판단 권한은 그대로 | **대폭 감소** |
| 피부·시술팀 | 변화 없음 — 스테이션 화면으로 다음 환자를 미리 볼 수 있게 됨 | 감소 |
| 의료진 | 변화 없음 (비콘 소지만) | 없음 |
| 데스크 | 변화 없음 — 반납 임박을 화면으로 미리 봄 | 소폭 감소 |

무전기는 없애지 않습니다. 상태를 묻는 무전이 사라지고, 돌발 상황·환자 컨디션 공유 등
원래 무전이 필요한 곳에만 남습니다.

## 5. 기대 효과

1. **액팅팀 과중 해소** — 상태 파악·지시 전파 노동이 시스템으로 이동 (무전 호출 수로 측정)
2. **환자 방치·방 공실의 자동 감지** — 사람이 발견하기 전에 화면이 먼저 경고
3. **대기시간 단축** — 빈 방 발생 → 다음 환자 배정 사이의 공백 축소
4. **운영 데이터 확보** — 단계별 대기, 방별 회전율·소요시간이 자동 축적되어
   병목 구간·예약 분산·인력 배치의 근거가 숫자로 남음
5. **외국인 환자 대응** — 언어 표시 + 통역 동행 누락 경고 (통역 위치도 추적 중)

## 6. 도입 계획

| 단계 | 내용 | 전제 |
|---|---|---|
| A | 보드 화면 개발 (읽기 전용) — 방 카드·환자 줄·의료진 줄 | 게이트웨이 전체 설치 |
| B | 드래그 배정 + 플랜 기입/팝업 + 경고 알림 | A |
| C | 각 팀 스테이션 화면 배포 | 접근 보안(비밀번호) 적용 |
| D | 코스(상담 유무 × 피부 전/후) 기반 "다음 단계" 자동 제안 | B 정착 후 |

각 단계 후 "무전이 실제로 줄었나"를 확인하고 다음 단계로 넘어갑니다.

## 7. 필요한 결정·지원

1. **게이트웨이 전체 설치 확정** — 존별 배치(약 50대, 5V USB 급전 배선 포함). 보드 정확도의 토대
2. **액팅팀용 태블릿** — 팀원·팀장 각 1대 이상 (이동하며 사용)
3. **스테이션 화면** — 읽기 전용 보드를 걸 모니터/태블릿 (데스크·피부실·시술부 등 3~4곳)
4. **운영 합의** — 인포팀 플랜 기입·상담팀 업데이트 절차를 팀 리더들과 확정

## 8. 프로토타입

`docs/액팅보드_프로토타입.html` — 브라우저에서 열면 바로 동작합니다 (설치 불필요, 가상 데이터).

- 팀장 뷰: 의료진 위치 + 방치/초과 경고가 자동으로 뜨는 모습
- 대기 환자를 빈 방에 끌어다 놓기 → 안내 전송 → 도착 자동 처리
- 환자 이름 클릭 → 플랜 확인·업데이트
- 팀원 뷰 / 읽기 전용(스테이션) 전환

액팅팀 팀장 검토를 마쳤고, 본 보고의 개선 사항(플랜 기입, 드래그 배정)이 반영된 버전입니다.
