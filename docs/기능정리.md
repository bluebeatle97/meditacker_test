## 1. 시스템 한눈에 보기

BLE 비콘(태그)을 지닌 환자·직원의 신호를 게이트웨이가 스캔 → 서버가 **존(방) 단위**로 판정
→ 권한별로 걸러 세 화면에 실시간 표시.

```
비콘 (CP35 환자 / BP105N 직원)
  → 게이트웨이 (AB BLE Gateway V4, MQTT·MessagePack)
  → 서버 수신부  : 어댑터 자동 분기(실장비/목) → ScanRouter(화이트리스트 관문)
  → 존 판정 엔진 : RSSI 창 중앙값 → 히스테리시스 + 연속확인 → 존 확정 / 복도 / 자리비움
  → 좌표 추정   : RSSI 가중평균 → 존 목줄 → EMA 평활 → 속도제한 → 벽 안쪽 스냅
  → 배포        : /staff(직원용) · /patient(환자용, 익명화) · /monitor(관제, raw)
  ↘ 기록        : presence_logs(입퇴실) · navigation_logs(방 안내) · 스캔 녹화(ndjson)
```

| 화면 | 주소 | 대상 | 성격 |
|---|---|---|---|
| 직원용 패널 | `:5173` (배포 시 `/`) | 인포·간호사·의사 | 실제 도면 + 전체 위치 + 등록/반납 + 방 안내 |
| 환자용 패널 | `:5174` (배포 시 `/patient/`) | 환자 본인 폰 | 도트맵 + 본인 위치 + 길 안내 화살표 |
| 관제 페이지 | `:8080/monitor` | 운영자·현장 튜닝 | raw 신호·판정 원재료 + 하드웨어 등록 |

패키지: `server`(Node/TS) · `web-staff` · `web-patient`(둘 다 Phaser) · `shared`(공용 타입·계산).

### 용어 (NEXT.md 합의)

- **등록** = 관제에서 비콘을 하드웨어 화이트리스트에 올리는 것 (비콘당 평생 1회)
- **환자 등록(배정)** = 사람에게 비콘을 넘기는 것 (방문마다, 직원용 패널에서)
- 비콘 생애: `등록(1회) → 창고 ⟷ 환자 등록(올 때마다) → 환자 손 → 반납 → 창고`
- **배정된 것만 화면(지도)에 나온다.** 미배정(창고)은 등록/반납 목록에서만 보인다

## 2. 직원용 패널 (web-staff)

### 2.1 실시간 위치 지도 (기본 화면)

- 실제 도면 위에 비콘 아바타(그룹 색 점 + 이름표)가 표시된다. 이름 없으면 태그 ID 뒤 5자리, 메모 있으면 `📝`.
- 아바타는 순간이동하지 않고 **A\*로 벽을 피해 걸어서** 이동한다. 신호 끊긴 비콘은 도면 밖 우상단 `자리비움` 칸으로 치워진다.
- 아바타가 겹치면 자동으로 비켜서고, **점을 클릭하면** 왼쪽 목록의 해당 줄이 열린다.
- 복도는 존이 아니므로 `복도 이동 중` 으로 별도 표시. 목록의 '구역'은 4.5초 이상 머문 곳만 반영(스침 방지).

### 2.2 화면 조작 (우측 버튼열)

| 버튼 | 기능 |
|---|---|
| `🔍 − 100% +` | 확대/축소(휠 가능)·원래 크기. 100% 초과 시 드래그 이동. 220% 이상에서 게이트웨이 라벨 표시 |
| `🏷 이름 보기/숨기기` | 방 이름 + 도면 주석(가구·설비) 라벨 토글 |
| `🚧 통제구역 보기` | 통행 불가 격자(벽·샤프트)를 빨간 반투명으로 표시 — "왜 저리로 돌아가지" 확인용 |
| `📡 게이트웨이` | 3단 순환: 담당 구역(어느 GW가 이기는 자리인지 색칠 — **오판 예상 지점 확인**) → 수신 세기(초록~빨강) → 끔. 마커 클릭 시 한 대만 보기. ⚠️ 모델 예측이지 실측 아님 |
| `🧪 테스트 장비 켜기/끄기` | 목 게이트웨이·목업 비콘을 **서버 관문에서** 차단(화면 필터 아님 — 판정·로그·관제 전부에서 빠짐). 전환 시 자동 새로고침 |
| `👥 환자 등록/반납` | 인포 데스크 화면 (2.4) |
| `🎮 환자용 패널` | 환자용 앱 새 탭 |
| `⚙ 관리자 모드` | 관제 페이지로 이동 |

### 2.3 비콘 목록 패널 (좌측)

- 그룹 버튼 5개(색·인원수 표시): `의사`(파랑) `간호사`(민트) `통역`(보라) `환자`(노랑) `미지정`(회색). 누르면 그 그룹 목록이 펼쳐진다.
- **지금 추적 중인(배정된) 비콘만** 나온다. 창고 비콘은 환자 등록/반납 화면에서.
- 한 줄: 강조 아이콘(맵에서 찾기) · 이름 편집 · 팔찌 6자리 · 그룹 변경 · 신호등(6초내 초록/15초내 노랑/이후 회색) + 구역 + 체류시간 · 메모 편집.
- 이름·메모·그룹 변경은 서버(`/tag-meta`)에 즉시 저장되고 전 화면에 동기화된다.

### 2.4 환자 등록 / 반납 (인포 데스크)

`👥 환자 등록/반납` 모달. 필터 `전체 / 배정중 / 창고`. **이 화면만 재고 전체를 본다.**

| 동작 | 흐름 |
|---|---|
| 환자 등록 | 창고 비콘의 `환자 등록` → 이름 수기 입력 → 그 순간부터 지도에 표시. 배정마다 내부적으로 새 사람이 생겨 오전/오후 환자의 기록이 섞이지 않는다 |
| 반납 | `반납` → 추적 중지 + 캐릭터 설정 초기화 + 걸린 안내 해제 |
| 입장 초기화 | QR 로 입장한 환자가 폰을 바꿨을 때 — 클레임을 풀어 QR 재스캔 가능하게 |
| 방 안내 | 환자 줄의 `🧭 방 안내…` 드롭다운 (2.5와 동일) |

창고 비콘에는 마지막 신호 경과(`창고 · N분 전`)가 표시된다 — 배터리 사망·분실 확인용.

### 2.5 방 안내 (직원 → 환자)

- 비콘 목록/등록화면의 **환자 줄에만** `🧭 방 안내…` 드롭다운. 고르는 즉시 안내가 걸리고, 환자 폰에 빨간 화살표가 뜬다.
- 목적지 후보 27개: 환자 구역 + 대기 + 접수, 단 직원 전용 구역 안의 방은 제외(서버도 이중 검증).
- 안내 중이면 `→ 목적지` 배지 + `안내 끝` 버튼. **도착하면 서버가 자동 해제**하고 소요 시간이 `navigation_logs` 에 남는다.
- 안내 중인 환자를 강조(선택)하면 도면에 **빨간 경로선**이 그려진다(환자 화면과 같은 A\*·같은 경로 — 두 화면이 다른 길을 보여주지 않게).

### 2.6 장기체류 경고

- 같은 자리(안정화된 표시 구역 기준) **10분 이상** 머문 `환자`·`미지정` 비콘을 화면 상단 빨간 경고창에 띄운다. 의사·간호사·통역은 제외(한 방에 오래 있는 게 정상).
- 이름 클릭 → 카메라 이동 + 강조 + 목록 열기. `확인` → 그 자리에 한해 알림 끔(자리를 옮기면 다시 뜸).
- 맵 아바타·목록 줄·경고창·그룹 버튼 네 곳에 같은 박자로 `!` 가 깜빡인다.

### 2.7 시연 모드

서버 응답이 없으면(GitHub Pages 등) 자동으로 가상 데이터 모드로 전환. `시연용 가상 데이터` 노란 배지가 항상 뜨고(지우지 말 것), 관리자 모드·등록/반납·테스트 장비 버튼이 사라진다.

## 3. 환자용 패널 (web-patient)

### 3.1 입장 — 팔찌 번호 / QR

토큰 결정 3갈래 (`resolveToken`):

1. `?token=` 있으면 바로 진입 (dev-seed 가 찍어주는 링크 등)
2. `?pin=` 있으면 (팔찌 QR) 즉시 입장 시도 — **처음 찍은 기기가 그 팔찌를 차지**(claim). 성공 시 주소를 `?token=` 으로 교체해 새로고침에도 안전. 예전 환자가 브라우저 기록으로 다시 들어와도 `이미 사용 중` 거부
3. 둘 다 없으면 **팔찌 번호 입력 화면**: "받으신 팔찌에 적힌 6자리 번호를 입력해 주세요" → `입장하기`. 오류 문구를 그대로 보여준다(`없는 번호입니다` / `아직 등록되지 않은 팔찌입니다` / `이미 사용 중인 팔찌입니다 — 데스크에 문의하세요` 등)

PIN = 비콘 MAC 뒤 6자리(팔찌 인쇄와 동일). 입장 화면은 Phaser 보다 먼저 떠서 구형 폰에서 지도가 안 떠도 번호는 넣을 수 있다.

### 3.2 캐릭터 만들기 + 별명 (첫 진입)

- 저장된 프로필이 없을 때만: `내 캐릭터 만들기` — 머리/옷/피부/눈/장식 432파츠 조합, 미리보기(서기/걷기/앉기), `🎲 아무거나` → `별명 정하기`(선택, 12자, 다른 환자에게 안 보임).
- 서버 `patient_profiles` 에 저장(브라우저 스토리지 금지 — 불변식 B-5). **반납하면 초기화.**
- 파츠 에셋이 없는 배포(재배포 금지 라이선스)에서는 고정 4종 선택으로 대체된다.

### 3.3 본인 위치 지도 (도트맵)

- 층 전체를 다시 그린 타일 도트맵. 카메라가 내 캐릭터를 따라간다(정수배 줌).
- 내 캐릭터는 청록 링 + 머리 위 화살표로 강조. 별명이 있으면 이름표.
- 멈춰 있고 앉을 만한 방(대기/상담/회복/피부관리)이면 앉는 자세.
- 우하단 `🗺 전체 보기 ↔ 📍 내 위치` 토글 — 유일한 상시 조작 버튼.

### 3.4 상단 HUD

`{별명} 님` / 현재 방 이름(4.5초 안정화, 복도는 `복도 이동 중`) / `{방}에 N명`(구역 인원수). 대기 순번·예상 시간 자리가 있으나 서버가 아직 0 을 보낸다(Phase 2).

### 3.5 길 안내 (화살표)

- 직원이 걸어야 나타난다(환자 쪽 목적지 선택 UI 없음).
- 상단 빨간 띠 `{방 이름} 으로 가주세요` + 발밑에서 목적지까지 **바닥 화살표 줄**(목적지 쪽으로 밝기가 흐름, 지나온 자리는 지워짐).
- 경로는 직원 전용 구역을 피하고 복도를 우선, 가로·세로 직선으로만. 도착하면 `도착했습니다` 초록 띠 4초 후 사라짐.

### 3.6 주변 사람들 (혼잡도 체감)

- 다른 손님·직원이 익명 도트 캐릭터로 함께 보인다. 넘어오는 정보는 **익명 id·좌표·손님/직원 구분뿐**(이름·MAC 절대 안 나감). 직원은 항상 같은 스킨으로 구분.
- 진료 관련 방(사적 공간 마스크) 안의 사람은 목록에서 빠진다.
- `PATIENT_SEES_EVERYONE=0` 으로 통째로 끌 수 있다 (⚠️ 현재 기본 on — 9.2 참고).

## 4. 관제 페이지 (/monitor)

서버가 직접 서빙(별도 빌드·CDN 불필요, 폐쇄망 대응). 원본 신호를 **안정화 없이** 그대로 보여준다 — 현장 튜닝용.

| 패널 | 기능 |
|---|---|
| 헤더 | 연결 표시등 · 추적 태그 수 · 게이트웨이 N/M 온라인 · 스캔/s · 누적 · 미등록 차단 수 · 가동 시간 · `🧪 테스트 장비` 토글 · `← 직원용 패널로` |
| **미등록 신호** | 화이트리스트에 걸러진 주변 BLE 목록 (RSSI 센 순 — 게이트웨이 코앞에 댄 비콘이 맨 위). `[등록]` → 분류+이름+설명 입력 → 즉시 추적 시작. **비콘 100개 일괄 등록이 이 화면** |
| 게이트웨이 | ID·라벨·존·스캔 수·최근 수신(10초 신호등). `[구역 변경]` 로 재시작 없이 존 재배정 |
| **미등록 게이트웨이** | 신호를 보내온 미등록 GW 목록 — 설치 구역 선택 후 `[등록]` → `gateways.json` 기록 + 재시작 없이 반영. (장비 스티커 MAC 과 페이로드 MAC 이 달라 이 화면이 필수) |
| 태그 상태 | 태그별 카드: 이름/그룹/존/최근 수신 + **게이트웨이별 RSSI 상위 6** (존 판정의 원재료) + `[✎ 이름/그룹]` |
| ● 녹화 정답 마크 | 녹화 중일 때만: 존 선택 + `[지금 이 방에 들어옴]` / `[추적구역 이탈]` — 리플레이 채점 기준 |
| 실시간 스캔 피드 | 시각·GW·태그·dBm (어댑터 동작·신호 세기 확인) |
| 존 전환 로그 | 전환 이력 — 채터링 육안 확인 |

⚠️ **무인증.** 태그 위치 전부가 노출되므로 운영 배포 전 인증/망 분리가 필요하다 (9.1).

## 5. 서버 내부 동작 (요약)

### 5.1 존 판정

- 게이트웨이별로 3초 창(`RSSI_WINDOW_MS`) 안 샘플의 **중앙값**으로 비교 (단발 RSSI는 ±3~6dB 튐).
- 가장 센 게이트웨이의 존이 후보. 현재 존보다 `HYSTERESIS_DB`(8) 이상 세고, 연속 `CONFIRM_COUNT`(3)회 이기면 전환 확정.
- **복도 판정**: 최강 대비 6dB 안에 드는 게이트웨이가 서로 다른 존 3개 이상이면 `inTransit`(복도) — 복도에 GW 가 없어도 "시술실 2 체류 1분" 같은 오표시가 안 나게.
- 15초 무신호 = 자리비움(상태 유지), 10분 = 메모리에서 삭제.
- 판정은 200ms 배치(`ZONE_EVAL_MS`) — 초당 1,000건 이상에서도 부하가 태그 수에만 비례.

### 5.2 좌표 추정 (지도 위 움직임)

들리는 **모든** 게이트웨이 좌표의 RSSI 가중평균 → 존 중심 320px 목줄 → EMA 평활(0.35) → 속도 제한(2.2m/s) → 벽 안쪽 스냅. 프론트는 그 좌표 사이를 A\* + 구간별 속도 재계산(walk-pacing, shared 공용)으로 걸어서 메운다 — 직원용·환자용이 같은 위치·같은 길을 보여준다.

### 5.3 권한·프라이버시

- 소켓 네임스페이스 분리 + JWT 타입 검증 (환자 토큰으로 /staff 접속 불가).
- 환자 화면: 손님 비콘만, 익명 id 로만, 진료실 안 사람은 좌표 숨김. 직원 위치는 익명으로도 안 나감.
- 직원 화면 권한 필터: 환자 본인만 / 간호사 담당구역+같은 과 / 의사·관리자 전체. (⚠️ 좌표 방송 `pos:update` 는 아직 필터 미적용 — 9.1)
- 화이트리스트 기본 on: 등록된 비콘만 통과. 미등록 신호는 임시 버퍼(200개·60초)에만 담기고 판정·로그에 안 들어간다 — 동의 없는 단말 수집 방지.

## 9. 알려진 위험 (운영 전 정리 필요)

### 9.1 인증 — 핀 한 겹 ✅ (2026-08-18)

직원용·관제에 **진입 핀**이 걸렸다. 무인증 API 는 목록 한 곳(`index.ts` 의 `STAFF_ONLY`)으로 일괄 이동했고, 관제 소켓(`/monitor`)에도 staff 토큰 검사가 붙었다. `/dev-token` 과 채널톡 손테스트 창구는 개발 모드에서만 존재한다(운영 404). 핀은 `STAFF_PIN` 환경변수 한 곳.

남은 것: **핀 한 겹이 전부다.** 계정별 로그인·감사로그는 없고, 핀을 아는 사람은 전원의 실명·위치를 본다. 공개 URL 이면 6자리보다 긴 핀을 쓴다(잠금은 IP 기준이고 프록시 헤더를 믿는다). 환자용은 의도적으로 핀이 없다.

### 9.2 `PATIENT_SEES_EVERYONE` 기본 on

환자 화면에 익명 좌표가 나가는 현재 기본값은 설계 불변식 B-1 의 예외 상태다(익명 id 뿐이라 실익 대비 위험은 낮지만, 문서상 불변식과 코드 기본값이 어긋나 있다). 운영 정책 확정 후 기본값 또는 불변식 문구 한쪽을 맞출 것.

### 9.3 DB 단일 파일 · 백업 없음

태그 등록·환자 프로필·동선 로그 전부가 서버 PC 한 대의 SQLite 파일. 실측 전후 수동 복사에 의존 중.

### 9.4 서버 자동 시작 없음

재부팅하면 아무것도 안 뜬다(README 복구 절차 참조). DHCP 로 IP 가 바뀌면 게이트웨이가 브로커를 잃는다 — 공유기 DHCP 예약이 선결.

### 9.5 설계서 ↔ 구현 어긋남 (문서 갱신 대상)

## 10. 다음 단계 제안

업무 프로세스 확정 전이라도 방향이 서 있는 것들. **A 는 운영 개시 전 필수, B 는 업무 효율, C 는 데이터 활용.**

### A. 운영 전 필수

1. ~~**직원용·관제 인증 한 겹**~~ ✅ 진입 핀 + `STAFF_ONLY` 일괄 이동 완료 (9.1). 다음은 계정별 로그인·감사로그
2. **서버 자동 시작 + DHCP 예약** — Windows 서비스(nssm/작업 스케줄러) 또는 PM2. 재부팅 복구 절차가 사람 손을 안 타게 (9.4)
3. **DB 자동 백업** — 하루 1회 `meditracker.db` 스냅샷을 다른 위치로 (WAL 체크포인트 후 복사면 충분) (9.3)
4. **자동 반납** — NEXT.md 6단계 그대로 (보관함 안 게이트웨이, −35dBm·5분)

### B. 업무 효율 (프로세스 들어보고 우선순위 확정)

5. **대기열 실동작 (Phase 2)** — `assignments.assigned_at` + 존 체류로 대기 순번·예상 시간 계산. HUD 자리는 이미 있음
6. **알림톡/알림 발송함** — `navigation_logs.onEvent` 에 구독자만 붙이면 됨. "N번 방으로 오세요" 를 화살표+메시지 이중으로
7. **직원 빠른 찾기** — "김원장 지금 어디" 검색/고정 표시 (`person:locate` 이미 있음, UI 만)
8. **접수 시 QR 인쇄물 흐름 확정** — 고정 IP 후 QR 인쇄 (NEXT.md 미해결)

### C. 데이터 활용 (지금도 쌓이고 있는 것)

9. **환자 여정 타임라인** — `presence_logs` 로 환자별 "접수 10:00 → 대기 23분 → 상담실2 15분 → …" 조회 화면. 상담 지연·병목 방이 숫자로 보임
10. **일일 운영 리포트** — 방별 회전율·평균 체류·장기체류 발생 건수·안내 소요시간(`navigation_logs.travel_sec`) 요약
11. **혼잡 시간대 분석** — 존별 시간대 점유 히트맵 (게이트웨이 배치 조정·예약 분산 근거)
